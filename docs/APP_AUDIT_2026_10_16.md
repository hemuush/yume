# App audit — 16 October 2026

This review covers the local working tree after the shared popup refinements. It is not device acceptance or a guarantee that every execution path is defect-free. No APK was built and no changes were pushed for this audit.

## Coverage and method

The source inventory read 413 production JavaScript/TypeScript files (about 67,000 lines) under `app`, `src`, `plugins` and `scripts`. Test/support files were excluded from that production count. Repository-wide lint, formatting and type checking complement this mechanical inventory; reading a file into a scanner does not constitute a line-by-line human review.

The focused source review followed startup, lock/privacy/theme preferences, screen loading and freshness, shared modal/header/footer/amount-pad handling, nested loan/account/goal tasks, transaction validation, loan payments, goal reservations, backup discovery/restore, notification planning/rebuild and widget privacy. Feature-level regression coverage includes Home, Activity, Plan, Reports, add/split/labels/refunds, accounts/settings/categories, loans, recurring, goals, people, budgets, Garden, Wrap and backup.

## Findings fixed

1. **Cold-start masking gap:** financial screens could mount before the saved sensitive-amount preference loaded. Root startup now awaits it before mounting those screens. A failed preference read stays on the startup error/retry path. Tests hold the read pending and reject it to verify that financial screens remain unmounted.
2. **Stale privacy reads:** startup or restore reads could overwrite a newer eye-toggle choice or a newer restore. Generation checks now reject those older responses and invalidate reads on unmount.
3. **Overlapping unlock attempts:** repeated reveal taps could open multiple authentication attempts, and a late successful unlock could supersede a restored privacy setting. One authentication attempt runs at a time; an overtaken result cannot reveal amounts. Cancellation/failure keeps masking enabled.
4. **Stale theme reads:** a delayed startup/restore response could replace a newly selected theme. Theme reads now follow the same latest-choice rule.

The palette, category-based privacy scope, database schema, financial calculations and persisted-record formats are unchanged. No speculative layout redesign or broad data-layer rewrite was included.

## Still requires a phone

- Keyboard and amount-pad behavior, especially label editing, short screens and switching between system keyboard and numeric pad.
- Calendar centering, long labels, large amounts and enlarged system text without clipping.
- Native parent/child modal transitions and Android Back behavior in loan, account and goal tasks.
- Save/restore busy states, permission revocation and storage-picker behavior on Android.
- Actual scheduled notification delivery with the screen locked, battery restrictions and device restart.
- Biometric/device-unlock prompts, screenshot/recent-app privacy, widgets and upgrade installation.

Use [release device checks](RELEASE_DEVICE_CHECKS.md) for manual acceptance. Automated mocks cannot establish native visual quality, notification delivery, or real-device performance. No claim of “perfect” UI or production sign-off is made while these checks remain unperformed.
