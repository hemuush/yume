# Release device acceptance

Use the new candidate containing notification delivery diagnostics and lifecycle fixes. Build 10 contains native privacy hardening but does not contain those notification follow-ups. Test on copied data or a spare device; preserve an independent backup before any restore. Do not change the phone clock or clear your real app data for these checks.

Record: APK/build ___; phone/model ___; Android ___; launcher ___; date ___; tester ___ .

| Area                      | Action                                                                                               | Expected result                                                                                                                     | Actual/status |
| ------------------------- | ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ------------- |
| Upgrade                   | Install over the current app, open Home/Activity/Plan/Reports                                        | Existing balances, entries, loans, goals and settings remain; no unwanted onboarding                                                | Not run       |
| Fresh install             | Use a spare device/install without prior data                                                        | Onboarding finishes; an account can be created and first entry saved                                                                | Not run       |
| Permission/channel        | Notifications → Delivery check; test permission and reminder category separately                     | Correct blocked status; permission prompt works; a denied test is not reported as sent                                              | Not run       |
| Immediate notification    | Tap Test notification, open notification tray and tap the notification                               | Amount-free Yume test appears and opens Add; tray visibility matters even when sound/head-up is off                                 | Not run       |
| Timed evening reminder    | On a day with no manual entry, enable an upcoming Evening slot; background without force-stop        | Logging nudge appears around that slot. Android inexact alarm/battery policy can delay it; record actual delay                      | Not run       |
| Conditional reminders     | Log today before Evening; use a due EMI/wrap/alert for Morning                                       | Evening log-only nudge is absent after logging; Morning is absent when nothing is due. At most one merged notification per slot     | Not run       |
| Renewal/change            | Background/resume; change times; edit/delete/undo a today's entry; tap Rebuild reminders             | Scheduling status stays usable and follows the latest enabled times/data, with errors surfaced                                      | Not run       |
| Notification restrictions | Test with battery saver/restrictions and DND, then normal settings                                   | Record delivery/tray/sound differences; no assumption that app permission alone guarantees alarms                                   | Not run       |
| Lock                      | Enable, cancel unlock, unlock with PIN/biometric, leave >1 minute, return                            | Cancellation stays locked; correct authentication unlocks; return relocks; no private app-switcher preview                          | Not run       |
| Widgets                   | Add all five, toggle hide-values, record a transaction, resize, reboot; test default launcher change | All render/update/open correct routes; hidden values remain hidden. Non-default/custom widget hosts are not automatically supported | Not run       |
| Transaction integrity     | In a test account add ₹100 expense, edit to ₹150, delete, undo                                       | One saved entry; balance/spending change by exact expected amounts; undo restores the same entry                                    | Not run       |
| Transfers/refunds         | Transfer between test accounts, record a refund, try incompatible currencies                         | Transfer preserves combined money; refund lowers spend and increases receiving balance once; cross-currency transfer is rejected    | Not run       |
| Loan/people/goal          | Pay/undo an EMI, settle with/without an account, add/release a reservation                           | Loan schedule/ledger agree; balance-only settlement creates no account entry; reservation does not change account balance           | Not run       |
| Restore success           | Export a copied test dataset, alter it, restore then put back the recovery copy                      | Counts/balances/links match each snapshot; status identifies the actual saved recovery data                                         | Not run       |
| Restore failures          | Invalid/newer-format JSON, revoked folder access, insufficient storage on a test device              | Clear failure; original data preserved. No overwriting a newer folder backup without review                                         | Not run       |
| Native UI                 | Add calculator/keyboard, calendar, Reports detail, Loans/Recurring/Goals; enlarged text/long names   | Scroll reaches every action; pinned controls stay clear of keyboard/nav; no clipping or empty sheets                                | Not run       |
| Performance/accessibility | Realistic dataset, repeated scrolling/tab changes, reduced motion, screen reader                     | Record visible stalls and measured frame behavior if available; controls are reachable and labels useful                            | Not run       |

Technical gates separate from this manual checklist: inspect final APK/AAB permissions and provider, signing continuity and manifest; confirm unrelated-app widget-image denial with a technical harness when available; validate production AAB/native libraries and store declarations. Source checks are not a substitute for device presentation/delivery. Report failures with the build, phone/OS, exact steps and expected versus actual result; do not mark an unperformed check passed.
