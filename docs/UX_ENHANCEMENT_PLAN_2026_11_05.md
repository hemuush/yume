# UI/UX enhancement direction — 5 November 2026

The design goal is a calm money companion with clear next actions, readable figures and predictable navigation. Preserve Yume's cream/pastel themes and local-first behavior. Increasing decoration or shortening every animation would not, by itself, improve the experience.

This plan draws on the current routes, shared components, maintained architecture and prior source audit. It is not a claim that every screen has been visually accepted on the Pixel 10a. The recent smoothness work and its phone-test limitations are recorded separately in [the smoothness review](SMOOTHNESS_REVIEW_2026_11_05.md).

## Implemented in this enhancement pass

- **Consistent empty-state hierarchy:** shared headings use the standard title size, supporting text uses the readable secondary color, and text/action columns are bounded to a comfortable width. Headings are exposed to accessibility services. Text remains scalable and wrapping; buttons retain existing touch targets and press/reduced-motion feedback.
- **People first use:** explain the purpose and place Add a person beside the explanation. It opens the same existing setup form as the header action.
- **Recurring first use:** place Add a recurring entry beside the explanation when an account exists. The existing account prerequisite still provides Add an account instead.
- **Activity recovery:** filtered empty results offer Clear filters in place. It clears type/category/account/label together, using the same action as the filter chips, without moving the selected period or discarding transactions.

These shortcuts open forms or change view filters; they do not bypass financial validation or write records automatically.

Validation for this pass: 367 Jest suites passed (11,798 tests; two existing skips), including direct first-use actions and filtered-results recovery. Android JavaScript export succeeded. These checks do not establish native frame pacing, screen-reader output or physical-device visual acceptance.

## Animation principles

Use motion to explain a state change: press feedback, a selected tab, a panel opening or a successful save. Content and actions should not wait for decorative entrances. Prefer opacity/transforms for screen motion; reserve layout animation for genuine reordering or disclosure. Keep scrolling/dragging tied to touch and cancel obsolete animations when the user changes direction. Always provide a static reduced-motion path.

The next performance work should be selected from an actual release trace: JS-driven period swipes and row dragging, large expanded Activity groups, and nested sheet/keyboard movement are candidates. Source inspection alone does not prove which is the Pixel 10a's current bottleneck.

## Rollout

Keep enhancements small and reviewable on `improve/app-smoothness`. For each flow, test primary action, cancel/back, failure/retry, privacy, large text and reduced motion before broadening it. Capture phone screenshots and release frame timings before claiming a whole-app visual redesign or a measured responsiveness improvement. Financial semantics, saved data and familiar destinations take priority over cosmetic novelty.
