# Expo SDK 58 upgrade

Recorded 21 October 2026, replacing SDK 57. Validation was desktop-only (Node 22.22, `TZ=Asia/Kolkata`); no APK was built and no phone or emulator was used.

## Sources

The Expo docs site was unreachable from the build sandbox. The upgrade used instead: the SDK 58 `bundledNativeModules.json` and per-package `CHANGELOG.md` files on Expo's `sdk-58` branch, the React Native 0.87/0.88 changelog, and the type definitions and sources of the installed packages. `expo install` also needs Expo's API, so versions were pinned by hand from that file and checked against it afterwards: all 31 SDK-managed dependencies match.

## Held back on purpose

Each hold was tried in a scratch copy, not only read from peer ranges.

- **TypeScript 7:** `tsc` 7.0.2 runs once `baseUrl` is replaced by relative `paths`, and type-checks this project in 2.8s against 3.2s for TypeScript 6.0.3 (same zero errors). That gain does not justify an extra aliased compiler, and `eslint-config-expo` cannot load with TypeScript 7 as the main `typescript` package (`typescript-eslint` supports only versions below 6.1). TypeScript stays on 6.0.3; revisit when `typescript-eslint` supports 7.
- **React 19.3.1 and `react-native-keyboard-controller` 1.22.8:** React Native 0.88 (the newest release, no patch yet) ships a renderer built from React 19.3.0 and its peer range technically allows 19.3.1, but 19.3.0 is the tested combination and the SDK pin. Keyboard-controller 1.22.8 changes only an Android status-bar call, iOS code and a chat scroll view that Yume does not use. CI runs `expo-doctor`, which compares packages with the SDK's pins, so both stay on the pin until Expo publishes an SDK patch that moves it.

## ESLint 10

`eslint-plugin-react` 7.37.5 and `eslint-plugin-import` 2.32.0 (both latest, both required by `eslint-config-expo` 58) call `context.getFilename()`, which ESLint 10 removed, and crashed linting. `eslint.config.js` now wraps every plugin once with `fixupPluginRules` from ESLint's `@eslint/compat`, and `package.json` overrides tell npm those two plugins accept the installed ESLint. Planting one violation per plugin family (`typescript-eslint`, `import`, `react-hooks`, `react`) gave identical reports on ESLint 9 and ESLint 10, and the whole codebase lints clean. A clean `npm ci` reproduces it. Remove the wrapper and the overrides once those plugins release ESLint 10 support. `eslint-plugin-expo` still installs its own nested ESLint 9, which linting does not use. `.npmrc` keeps `legacy-peer-deps=true`: re-checked, npm would otherwise add `react-dom` 19.3.1 and `react-native-gesture-handler` 3.4.0 against the SDK pins (19.3.0 and ~3.3.0).

## GitHub Actions

`actions/checkout` moved from v4 to v7.0.1 and `actions/setup-node` from v4 to v7.1.0, still pinned by commit. Checkout 7 blocks fork-PR checkouts for `pull_request_target` and `workflow_run`; `ci.yml` uses `pull_request`, and `eas-build.yml` only proceeds for a same-repository push to `main`. `setup-node` 5 to 7 run on Node 24 (needs a current runner), cache npm automatically (this repo already sets `cache: npm`) and drop the dummy `NODE_AUTH_TOKEN` (this repo sets no `registry-url`). The workflow files parse as YAML, but no workflow was run.

## Code changes the upgrade required

- **Tab bar.** Expo Router 58 gives a custom `tabBar` `emitter` and `navigateToTab` instead of `navigation`. `PillTabBar` kept its behavior (press event, prevented-default check, long press) on the new props. Left as it was, the first tab tap would have thrown.
- **`InteractionManager` removed in React Native 0.87.** `runWhenIdle` (`src/lib/runWhenIdle.ts`) uses `requestIdleCallback` with a 2 second deadline, so startup maintenance, notification rebuilds and the foreground catch-up cannot be starved.
- **`File.write` is now asynchronous** in expo-file-system 58. The backup export and the pre-restore safety copy now await it; before, sharing could have started before the file existed. The legacy database copy in `migrateDbFilename` was never awaited (`copy` was already asynchronous in SDK 57), so errors escaped its `try/catch` and the "main file last" ordering was not guaranteed; it is awaited now.
- **Strict TypeScript API.** Refs are typed by instance (`ScrollViewInstance`, `ViewInstance`, `TextInputInstance`, `FlatListInstance`). `useCollapsingHeader` takes an instance type.
- **Discard guard.** `usePreventRemove` kept its contract; `useDiscardGuard` is unchanged and now covered against the real router.
- **Removed `decode-uri-component` shim.** It existed only to patch `query-string`, which Expo Router 57 used. Router 58 no longer depends on `query-string`, so the vendored copy, its dependency and its override are removed. `scripts/uriDecoder.test.cjs` now fails if either package returns to the tree, and `src/lib/deepLinkParams.test.ts` checks Router 58's own parser: unicode, plus signs, repeated parameters and a 24 KB malformed value.
- **ESLint.** `import/namespace` is off because it cannot follow expo-notifications 58's re-exported Android enums (it reported existing members as missing); the TypeScript compiler already rejects a missing namespace member.

## Test tooling

- `react-test-renderer` 19.3.0 is now declared; `jest-expo` 58 no longer bundles it and 148 suites import it. `@testing-library/react-native` 14 is added only for Expo Router's testing library.
- Fonts are reported as loaded under Jest (`expo-font` is mocked in `jest.setup.ts`). Every `@expo/vector-icons` icon loads its font on mount; with `jest-expo` 58 and React Native 0.88 that rejected (`expo-asset` reads an asset registry `jest-expo` does not stub) and, before, set state outside `act()`. This also removed 46 `act()` errors per run.
- `jest.setup.ts` drops one repeated `expo-notifications` warning (`jest-expo` reports an Expo Go environment, so every importing suite logged that push is unavailable). Every other warning is kept. Console output of a full run went from 252 messages to 4 (the SDK 57 commit printed 253): three are the app's own failure-path logging in tests and one is an order-dependent `act()` warning in `PlanScreen.test.tsx` (`MonthlyPlanCheck`) that does not reproduce when any single test runs alone. The other `act()` warnings were fixed by awaiting the asynchronous loads their tests start (`FilterModal`, `GoalOverviewModal`, `TransactionDetailModal`, `PlanScreen`, `useEntryDraftRecovery`), and mocks now match the real return types (`rebuildNotifications` returns a boolean).
- Jest 30 also collects `.cjs` files; `jest.config.js` ignores them (they are `node:test` suites run by `test:security`).
- `src/components/RouterIntegration.test.tsx` runs the real Router 58 with `PillTabBar` and `useDiscardGuard`: tab switching, pressing the active tab, and the blocked-back dialog with Keep editing and Discard. Restoring the old `navigation`-based tab bar makes it fail with `Cannot read properties of undefined (reading 'emit')`.

## Dead code removed

A `knip` run (not added to the repo) found no unused files or dependencies. It found and this change removed: `paymentMethodLabel` (left over from the removed payment-method UI), unused re-exports (`MIN_SPLIT_PARTS`/`MAX_SPLIT_PARTS` from `db/splits.ts`, `TILE_COLUMNS` from `CategorySection.tsx`, the three Wrap beats from `WrapBeats.tsx`), surplus `export` keywords (`Chip`, `DUE_SOON_DAYS`, `PAYMENT_METHODS`) and three unused style entries (`personAmt`, `compactHint`, `headLink`). `PUBLIC_CATEGORY_FAMILY` was unused only because `expenseLabels.ts` carried an identical private copy of the same SQL; that copy is gone and the shared fragment is used, with identical SQL. Remaining knip output is expected: Jest mock helpers reached through `require()`, the `expo-system-ui` decision, and `xcode` required by the security test through the `@expo/config-plugins` dependency. `assets/logo-mark.svg` is unreferenced but is the logo's vector master and was kept.

## Circular imports removed

The 13 cycles `madge` reported were one connected group of 13 modules. They are removed without changing behavior:

- `settings.ts` no longer imports `afterCommit.ts`. `setHideSensitiveAmounts` only saves; `saveHideSensitiveAmounts` (in `afterCommit.ts`) saves and then refreshes queued reminders, and `PrivacyContext` calls it. Both the failure result and the order of the two steps are the same.
- The database client no longer imports modules that import it: the currency cache moved to `currencyCache.ts`, `purgeExpiredDeletedEntries` to `deletedRetention.ts` (re-exported from `recentlyDeleted.ts`), and the `AppDb`/`SqlParam` types to `dbTypes.ts` (re-exported from `client.ts`).
- The alert builder reads categories through `categoryList.ts` (the read-only list, re-exported from `categories.ts`), so it no longer reaches the write code that triggers reminder refreshes.
- `QueuedAlert` and the notification routes moved to `queuedAlert.ts` (re-exported from `notificationPlan.ts`).

`scripts/checkCycles.cjs` (`npm run check:cycles`, also in CI) fails on a circular import among `src/` and `app/` modules. It uses the installed TypeScript parser, ignores `import type` and dynamic `import()`, and needs no new dependency. Checked three ways: it reports a planted two-module cycle, ignores a planted type-only loop, and reports the original SDK 57 tree as one 13-module group. A tool such as `madge` was tried first and rejected: it added 88 packages and could not skip type-only imports.

## Package alternatives considered

Measured from the Android bundle's source map (9.76MB of JavaScript source, 2,277 modules): app code 27%, react-native 23%, expo-router 13%, reanimated 9%, `xlsx-js-style` 6.7% (639KB), react-native-svg 2.8%.

| Candidate | Finding | Decision |
| --- | --- | --- |
| `expo-image` for `Image` | Two `<Image>` uses, both small local assets | No benefit |
| FlashList for lists | Only Activity can grow and it is already a windowed `FlatList`; its rows keep local state and measured-height drag ordering, which recycling would disturb | Not without phone profiling |
| Gesture Handler for swipe/drag | Four `PanResponder` uses; gains are plausible but unmeasured and need a refactor | Not without phone profiling |
| Skia for charts, MMKV, TanStack Query | Charts are small SVG; data is local SQLite; no server state | No benefit |
| Lighter spreadsheet writer instead of `xlsx-js-style` | Largest optional dependency (6.7% of source). It is only used to write; the known SheetJS 0.18 issues concern reading untrusted files. Replacing it means rewriting the styled export (`exportExcel.ts`, 631 lines) | Possible size saving, high rewrite risk; decide with startup measurements |
| SQLCipher via `expo-sqlite` (`useSQLCipher`) | Supported by the installed plugin. It would encrypt the database at rest, closing the gap that app lock does not encrypt SQLite. Needs a key store (a new dependency), migration of existing unencrypted databases and backup/restore changes | Not applied; needs your approval and a migration plan |

## Validation

- `tsc --noEmit`: 0 errors. ESLint: 0 problems. Prettier: clean. A clean `npm ci` from the committed lockfile in a separate directory reproduced the same results.
- `npm test`: 319 suites and 11,338 tests passed, 2 skipped. `npm run test:security`: 7 of 7. `node scripts/auditGate.js`: no blocking advisories (`braces` and `node-forge` allow-list unchanged).
- `npm run test:perf`: passed, including output parity.
- `npx expo export --platform android`: succeeded, 8.2MB Hermes bundle (2,301 modules), unchanged in size.
- `expo prebuild --platform android` in a scratch copy (release profile): the same blocked permissions, `exported="false"` widget receivers and caller-checked widget provider as SDK 57; Gradle 9.4.1.
- `expo-doctor`: 18 of 20; the two failures (config schema, React Native Directory) need Expo's servers.
