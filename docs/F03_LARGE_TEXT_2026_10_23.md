# F03 — 200% text and responsive shared controls

> Historical record: validation and implementation claims apply to the revision recorded below. For maintained behavior see [architecture](ARCHITECTURE.md); for the newer check results see the [repository re-audit](REPOSITORY_REAUDIT_2026_10_25.md).

## Root cause / change

Shared Text/TextInput capped the OS font scale at 1.3; the active tab label separately capped it at 1.15. Fixed-height keypad keys and one-line shrinking would still constrain text if only the cap changed.

The shared cap is now 2. Large-font labels wrap instead of shrinking, input minimum height includes its scaled line plus actual numeric padding/borders, keypad keys grow with layout scale, and the tab bar puts the active label beneath its four icon controls. PrimaryButton's animated text already reads the shared cap and its height can grow with content. The default font/layout scale remains 1.

## Tests and self-review

The first three UI regressions failed before the fix (cap 1.3, fixed 46dp key, one-line shrinking). A separate active-tab test exposed its 1.15 cap. Self-review added an input padding/border case which failed at 64dp rather than the required 74dp; the calculation was corrected before the completed full run.

All seven RNTL large-text tests pass, including live OS font changes and shared-listener cleanup. The focused controls/navigation/Add screen run also passed before the final padding case. Fresh full regression: **328 suites / 11,421 tests passed; 2 suites/tests skipped**, 454.0 seconds. TypeScript, whole-repository lint, formatting and cycle checks passed. The detailed reporter displayed diagnostics from unchanged partial-Router fixtures and negative-path tests; no lint warnings were introduced. No device/performance result is inferred from Jest timing.

No dependency, schema or financial behavior changes. The shared numeric snapshot avoids subscribing once per label to native OS events. Layout scale follows text at half rate and caps consistently at the supported 200% text scale.

Before/after policy: text 130% → 200%; active navigation label 115% → 200%; regular keypad fixed 46dp → minimum 69dp at 200%, with content allowed to grow. Input padding/border is included rather than assumed absent. No native frame/startup measurement is claimed.

## Android acceptance and risk

Rollback: revert this fix's commit; no migration is required. This restores the inaccessible smaller font caps.
